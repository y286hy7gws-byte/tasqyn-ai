# TASQYN AI

**Intelligent Urban Flood Monitoring & Risk Intelligence Platform**
Интеллектуальная система мониторинга подтоплений города **Павлодар**, Казахстан.
Категория: Smart City / AI / Urban Infrastructure / Environmental Monitoring.
MVP для **Idea Battle** (10 ноября).

---

## Что это

TASQYN AI превращает разрозненные сообщения жителей о подтоплениях в
структурированную городскую систему мониторинга:

1. Житель отправляет **фото + геолокацию + оценку глубины/проходимости**.
2. **AI-адаптер** анализирует фото и описание (реальный мультимодальный
   провайдер при наличии API-ключа; без ключа — прозрачный DEMO-режим).
3. **Risk Scoring Engine** формирует индекс риска 0–100 с расшифровкой
   каждого фактора.
4. Инцидент появляется на **интерактивной GIS-карте** (OpenStreetMap) и в
   **панели городских служб**.

> ⚠️ **Дисциплина данных.** Все синтетические записи помечены
> `is_demo = true` и визуальным бейджем **DEMO DATA**. Индекс риска — это
> индекс *срочности реагирования на сообщения*, а **не прогноз наводнения**.
> Демо-авторизация админа — **не** production-аутентификация.

## Технологический стек

- **Next.js 16** (App Router, cacheComponents) + **React 19** + **TypeScript strict**
- **Tailwind CSS v4** (кастомная тёмная дизайн-система)
- **Leaflet + React-Leaflet** · OpenStreetMap (тёмный рендер тайлов через CSS-фильтр)
- **Recharts** (графики), **Zod** (валидация), **Lucide** (иконки)
- **Supabase** (PostgreSQL + Storage + RLS) — при настройке; без ключей — локальный DEMO-режим на `localStorage`

## Режимы работы (автоопределение)

| | SUPABASE-режим | DEMO-режим |
|---|---|---|
| Условие | заданы `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ключей нет (по умолчанию) |
| Хранение | PostgreSQL `flood_reports`, `report_comments` | `localStorage` браузера |
| Фото | Supabase Storage (`flood-photos`), фолбэк — dataURL | сжатый dataURL (до ~1.2 МБ) |
| Заметность | бейдж `SUPABASE` | бейдж `DEMO MODE` + жёлтые метки DEMO DATA |

Если Supabase временно недоступен — приложение автоматически падает в
локальный режим (`degraded`), не ломая демонстрацию.

## Подключение Supabase (опционально)

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатный тир).
2. **SQL Editor** → выполните `supabase/migrations/0001_init.sql`
   (таблицы, триггеры, RLS-политики, bucket `flood-photos`, демо-записи).
3. **Project Settings → API**: скопируйте URL и anon-ключ.
4. Скопируйте `.env.example` → `.env.local` и заполните:

```env
NEXT_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-key>
```

5. Перезапустите `npm run dev`. Все страницы покажут бейдж **SUPABASE**.

`anon`-ключ безопасен для браузера: RLS разрешает всем только чтение и
создание инцидентов; изменение статусов/удаление — только `authenticated`.

## Настройка AI (опционально)

Редактируйте `.env.local` — достаточно **одного** ключа:

```env
# OpenAI vision (gpt-4o-mini)
OPENAI_API_KEY=sk-...

# или Google AI Studio (gemini-2.5-flash) — бесплатный тир
GEMINI_API_KEY=...
```

- Есть ключ → реальный мультимодальный анализ фото через
  `/api/ai/analyze` (в карточках появится метка **REAL**).
- Нет ключа → клиентская эвристика (статистика пикселей + ключевые слова),
  результаты помечены **DEMO** и `is_demo: true`.
- Ошибки провайдера, таймауты (~45 c) и отсутствие ключа не ломают отправку —
  система честно понижается до демо-анализа.

## Демо-авторизация админа

Пароль задают `NEXT_PUBLIC_ADMIN_PASSWORD`, по умолчанию **`tasqyn-admin`**.
Проверка выполняется на клиенте и показывается с предупреждением, что это
не production-аутентификация. Для production подключите Supabase Auth и
RLS-роль модератора.

## Демо-данные

`src/lib/demo-data.ts` — 22 синтетических инцидента в разных частях
Павлодара (набережная Иртыша, Центр, Сортировка, Затон, Ленинский район,
Кашканское озеро, Южный и др.):

- правдоподобные координаты в пределах городской территории;
- все уровни опасности и все статусы;
- свежие даты (0–9 суток) для живой аналитики;
- **помечены `is_demo = true`** и знаком DEMO/DATA во всех интерфейсах.

## Известные ограничения MVP

1. Аутентификация админа — клиентская (демо), нужна Supabase Auth для prod.
2. Демо-инциденты синтетические — не реальная гидрологическая картина.
3. DEMO-анализ — эвристика, а не модель CV (реальный AI требует вашего ключа).
4. Индекс риска не является прогнозом наводнения или гидрологической моделью.
5. Геокодирование адресов не подключено (координаты + ориентиры).
